Hummingbird Airlines — Service Directory

An example API application for exercising Aethrix Studio and learning API testing: one REST middleware in front of three simulated SOAP 1.1 legacy systems; live feeds (baggage claim board, bag scanner, gate turnaround) on SSE, gRPC, GraphQL and WebSocket; a downloadable contract for every surface. Study how the API is designed, then call it.

The four endpoints

EAI Gateway REST

Pure protocol translation: bookings CRUD, flight info, check-in, baggage drop. No business validation here.

  • Swagger UI
  • OpenAPI document
  • /api/v1/flights
  • /api/v1/bookings?passport=…

Booking System SOAP 1.1

Reservations system: CreateBooking, GetBooking, FindBookings, UpdateBooking, CancelBooking.

  • WSDL
  • POST /soap/booking
  • Action: http://hummingbird.airlines/booking/…

Flight Management SOAP 1.1

Airport flight control (read-only): SearchFlights, GetFlight. Statuses advance with the clock: scheduled → check-in open → boarding → departed.

  • WSDL
  • POST /soap/flights
  • Action: http://hummingbird.airlines/flights/…

Luggage Management SOAP 1.1

Airport departure control: one-shot CheckIn with a polymorphic bag array (at most one of each type) and single-bag RegisterBaggage; overweight accepted with a legacy warning.

  • WSDL
  • POST /soap/luggage
  • Action: http://hummingbird.airlines/luggage/…

Streaming & gRPC (baggage claim board)

Baggage Claim Board HTTP+SSE

Arrivals board of CDG Terminal 2E: belts (tapis) 1–5 fed by partner airlines (HB/AF/BA/CA/LH/EK), one arrival every six board-minutes. Add ?speed=60 to compress the clock and watch transitions within seconds.

  • GET /api/v2/baggage-claim (snapshot)
  • /api/v2/baggage-claim/{flightNumber} (404 ARRIVAL_NOT_FOUND)
  • GET /api/v2/baggage-claim/stream (live, resumable via Last-Event-ID)

BaggageClaimService gRPC

Unary + server-streaming over cleartext HTTP/2 (prior knowledge). Server reflection is enabled. Proto contract: /specs/baggageclaim.proto; a ready-made console client lives in tools/GrpcProbe.

  • BaggageClaim/GetBoard (unary)
  • BaggageClaim/GetArrival (unary, 5=NOT_FOUND)
  • BaggageClaim/WatchBoard (server streaming)
  • gRPC port: localhost:5007 (Grpc:HttpPort)

More protocols (bag scanner · GraphQL · gate feed)

BaggageScannerService gRPC bidi

Make-up room bag scanner: the client streams scans, the server streams one disposition per bag (accepted / duplicate / malformed / unknownZone / limitExceeded) and closes with a session summary after the client half-closes. No cross-session state; accepted bags are routed to belts by a deterministic hash.

  • BaggageScanner/ScanBags (bidirectional streaming)
  • Max 8 accepted bags per session, tag shape ^[A-Z]{2}[0-9]{6}$
  • Zones: MU1 (default) / MU2 / MU3
  • Probe: dotnet run --project tools/GrpcProbe -- scan

GraphQL HTTP + WS

Baggage claim board + departure check-in and bag drop: queries bagClaimBoard, bagClaimArrival (missing flight → error code ARRIVAL_NOT_FOUND), bagClaimBelt, subscription bagClaimEvents(speed, sinceSeq), and the mutations listed in the GraphQL operations table below.

  • /graphql (IDE and POST endpoint) — v1: flat bag input
  • /graphql/schema.graphql (v1 SDL)
  • /graphql/v2 (v2: same surface, bag inputs are oneOf variants)
  • /graphql/v2/schema.graphql (v2 SDL)
  • Subscriptions over graphql-transport-ws on the same URL

Gate turnaround feed WebSocket + REST

Departure-side gate board (gates 1–8, one Hummingbird rotation per gate every 16 feed-minutes): parking → boarding (+4) → final call (+8) → push-back (+10) → release (+12) → complete (+16).

  • GET /api/v2/gates (snapshot)
  • WS /api/v2/gates/ws — {"type":"subscribe","speed":60}
  • Frames: snapshot / gateEvent / ping-pong / error envelope

GraphQL operations — v1: POST /graphql · v2: /graphql/v2

Roots: Query, Mutation, Subscription. The subscription runs on the same URL over the graphql-transport-ws protocol. checkIn / dropBag travel through the same legacy luggage path as POST /api/v1/bookings/*, so error codes are identical across transports. scanBag sessions are scoped by the sessionId argument and expire after 30 minutes of inactivity. The table lists v1 (flat bag input); v2 serves the same operations with bags declared as oneOf variants (checked / carryOn).

Method / address Operation Arguments Returns · error codes (extensions.code)
POST /graphqlbagClaimBoard speed: Int = 1 BagClaimSnapshot (belts + arrivals)
POST /graphqlbagClaimArrival flightNumber: String!, speed: Int = 1 BagClaimArrival · errors: ARRIVAL_NOT_FOUND
POST /graphqlbagClaimBelt number: Int!, speed: Int = 1 BagClaimBelt or null
WS /graphqlbagClaimEvents speed: Int = 60, sinceSeq: Long = 0 BagClaimEvent stream (replays the backlog, then live)
POST /graphqlcheckIn input: CheckInInput! (bookingRef: ID!, bags: [BagInput!]) CheckInPayload (boarding pass + bags + warnings) · errors: BOOKING_NOT_FOUND, CHECKIN_CLOSED, ALREADY_CHECKED_IN, BAGGAGE_TYPE_LIMIT, FLIGHT_DEPARTED, INVALID_REQUEST, LEGACY_TIMEOUT, LEGACY_UNAVAILABLE
POST /graphqldropBag input: DropBagInput! (bookingRef: ID!, bag: BagInput!) DropBagPayload (full bag list + warnings) · errors: BOOKING_NOT_FOUND, CHECKIN_REQUIRED, CHECKIN_CLOSED, BAGGAGE_TYPE_LIMIT, FLIGHT_DEPARTED, INVALID_REQUEST, LEGACY_TIMEOUT, LEGACY_UNAVAILABLE

Failure injection (chaos header)

curl -H "X-HB-Simulate: timeout=12"   http://localhost:5000/api/v1/flights/HB903   # -> 504 LEGACY_TIMEOUT
curl -H "X-HB-Simulate: fault"        http://localhost:5000/api/v1/flights/HB903   # -> 502 INTERNAL_ERROR
curl -H "X-HB-Simulate: unavailable"  http://localhost:5000/api/v1/flights/HB903   # -> 502 LEGACY_UNAVAILABLE

The header also works when calling the SOAP endpoints directly, and is relayed by the middleware to the backends.

Reset demo data

POST /api/v1/admin/reset drops every booking, replays the five frozen demo seeds and restarts the deterministic counters — repeat a scenario without restarting the system. Global operation (no sessions, no concurrency guarantees); rate limits apply. 

curl -X POST http://localhost:5000/api/v1/admin/reset
